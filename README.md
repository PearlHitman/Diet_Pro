# Mise

Your AI sous chef. Pantry-aware recipes from what you already have.

**Live app:** [diet-pro-sigma.vercel.app](https://diet-pro-sigma.vercel.app)

AI-powered pantry-to-recipe PWA. Built with Vite + React + TypeScript.
Recipes generated by Claude (BYO API key, stored locally in your browser).

---

## Quick start (Windows)

### 1. Install Node.js (one-time)

Download the **LTS** version from <https://nodejs.org> and run the installer.
Click through with defaults. Open a new PowerShell window and verify:

```powershell
node --version
npm --version
```

Both should print version numbers. If "command not found", restart PowerShell.

### 2. Install project dependencies (one-time per clone)

```powershell
npm install
```

Takes ~30 seconds, downloads ~200MB into `node_modules`.

### 3. Run the dev server

```powershell
npm run dev
```

Vite will print two URLs:
- `Local: http://localhost:5173/` — open in your laptop's browser
- `Network: http://192.168.x.x:5173/` — open in your **iPhone's** Safari, same Wi-Fi

The iPhone URL is what makes this feel real. Hot-reload works on the phone too.

### 4. First-time setup inside the app

On first launch an **onboarding flow** walks you through everything:

1. Enter your name.
2. Set cuisine preference, cooking level, servings, allergies, diet goal, language.
3. Paste your Anthropic API key (get one at <https://console.anthropic.com/settings/keys>).
4. Add your first pantry ingredients.

After onboarding you land on the Home screen. You can revisit any of these
via the **Profile** and **Settings** tabs at any time.

### 5. Generate recipes

1. Tap **Generate** on the home screen.
2. Pick a meal type (Quick / Healthy / Comfort / Festive).
3. Wait ~15–20s — Claude generates 3 specific, non-generic recipes tailored to
   your pantry, expiry dates, skill level, and diet goal.
4. Browse results, tap a recipe for full steps, star favourites.

### 6. Install as a PWA on your iPhone

1. Open the Network URL (or the live Vercel URL) in Safari.
2. Tap the share button → **Add to Home Screen**.
3. It runs fullscreen, offline-capable, with no browser chrome.

When a new version is deployed, a gold banner appears at the top of the app —
tap **Update now** to get the latest build instantly.

## Features

### Pantry
- Add ingredients manually, by **photographing a product**, or by **scanning a supermarket receipt** — Claude (Haiku) reads the image and pre-fills the form.
- Ingredients are grouped by category (Produce, Protein, Dairy, Grains, Pantry, Other).
- Expiry tracking with colour-coded urgency dots; recipes prioritise "use soon" items.

### Recipe generation
- 3 recipes per generation, meaningfully different (different proteins, cuisines, techniques).
- Claude uses a creative-chef system prompt that bans generic titles and requires
  specific, evocative dish names and technique-rich steps.
- Model choice in Settings: **Sonnet** (default, fast), **Opus** (best quality), **Haiku** (cheapest — fine for testing).
- Vision calls (photo/receipt) always use Haiku regardless of model setting.

### Navigation
- Bottom tab bar: Home, Pantry, History, Favourites, Profile.
- Time-aware greeting on Home ("Good morning / Καλησπέρα…") with cuisine flag badge.

### PWA & updates
- Installable on iOS and Android.
- Service worker caches the shell for offline use.
- New deployments show an in-app update banner — no manual refresh needed.

### Internationalisation
- Full English / Greek (Ελληνικά) / Spanish (Español) support. Switch in
  Profile → Language.
- Generated recipes respect the language setting.

## How data is stored

Everything lives in your browser's **IndexedDB**. Keys under the `kitchen:` namespace:
`pantry`, `profile`, `recipes`, `settings`, `feed`, plus an `onboarded` flag.

**This means:** wiping browser data wipes the app. There is no cloud sync —
intentional for v1 (single-user, no auth, no privacy concerns).

To move between browsers or devices, use **Settings → Export data** (saves
a JSON file) and **Settings → Import data** on the other device. The export
is also a useful manual backup.

To reset: **Settings → Reset all data**.

## How recipe generation works

1. User picks a meal type on `/generate`.
2. `/generate/loading` calls `buildRecipePrompt()` from `src/lib/prompts.ts`,
   combining pantry items (with expiry urgency), profile, and meal type.
3. A **system prompt** establishes a creative-chef persona that rejects generic
   recipes and requires specific names, cuisine anchors, and technique-rich steps.
4. The Anthropic SDK is called directly from the browser
   (`dangerouslyAllowBrowser: true`). Your key never leaves your device except
   to `api.anthropic.com`.
5. Claude returns JSON; we validate the shape, build `Recipe` objects, save to
   IndexedDB, and show results.

To tune AI behaviour, edit **`src/lib/prompts.ts`** — all prompts live there.

## Deployment

The app is deployed at **[diet-pro-sigma.vercel.app](https://diet-pro-sigma.vercel.app)**.
Every `git push` to `main` triggers an automatic redeploy via Vercel.

To deploy your own fork:
1. Fork this repo on GitHub.
2. Go to <https://vercel.com> → Add New Project → select your fork → Deploy.
   Vercel auto-detects Vite. Done in ~1 minute.

## Troubleshooting

**`npm install` is stuck or fails.**
Run `npm install --no-fund --no-audit`. If still failing, delete `node_modules` and try again.

**iPhone can't reach the Network URL.**
Windows Firewall may be blocking. Allow Node.js when the popup appears, or
temporarily disable the firewall. Phone and laptop must be on the same Wi-Fi.

**"Invalid API key" but I just made one.**
Anthropic keys take ~30s to activate. Try again.

**Recipes come back in wrong language.**
Check Profile → Language. The generated recipes respect this setting.

**App icon is generic.**
Replace `public/icons/icon-192.png`, `icon-512.png`, `icon-512-maskable.png`
with your own icons. The SVG at `public/icons/icon.svg` is a placeholder.

**App isn't updating after a new deploy.**
Open the app — if an update is ready, a gold banner shows at the top.
Tap **Update now**. If no banner appears, force-close and reopen the app once.

## Known gaps

- **History date grouping** — the list is flat; design intent is sticky date headers ("Today", "Yesterday", "Mon Nov 3").
- **Pantry search / filter** — no text search or "show expiring only" toggle yet.
- **Regenerate one recipe** — results page has no per-recipe regenerate button; only full 3-recipe regeneration.
- **PNG icons** — only an SVG placeholder exists; proper 192/512 PNGs not yet generated.
